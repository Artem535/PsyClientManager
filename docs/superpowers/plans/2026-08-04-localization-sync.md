# Localization Sync (Issue #47) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Catch up `translation/app_ru.ts`/`app_en.ts` with every `tr()` string currently in source, remove the location-path noise that made a trial regeneration unstable across machines, and add a CI gate so this drift can never silently reappear.

**Architecture:** One-time `lupdate` regeneration (via the existing CMake `update_translations` target) with `-locations none -no-obsolete`, followed by manually written Russian translations for every resulting untranslated entry and identity English translations for the English side, then a new CI step that fails a PR if `lupdate` would still produce a diff.

**Tech Stack:** Qt6 Linguist tools (`lupdate`/`lrelease`, invoked via CMake's `qt_add_translations`), GitHub Actions.

- Per `AGENTS.md`: close the issue via `Closes #47` in the PR.
- Do not add new languages — this issue is only about consistency of the RU/EN pair already supported (out of scope per the design doc).
- The two source strings the original issue cited verbatim ("Title", "Apply") were not found anywhere in `src/` during the design phase — do not chase them further; the systematic catch-up below covers the actual current gap.

### Task 4: Add the CI translation-sync gate

**Files:**
- Modify: `.github/workflows/cmake-multi-platform.yml:210-212`

**Interfaces:**
- Consumes: `translation/app_ru.ts`/`app_en.ts` being fully in sync (zero-diff on `lupdate` re-run), as established by Tasks 1-3.
- Produces: a CI failure on any future PR that adds/changes a `tr()` string without updating the `.ts` files.

- [ ] **Step 1: Insert the check step**

In `.github/workflows/cmake-multi-platform.yml`, the `build` job currently has (around line 210):

```yaml
      - name: Configure
        run: cmake --preset vcpkg-release

      - name: Save vcpkg binary cache
```

Insert a new step between `Configure` and `Save vcpkg binary cache`:

```yaml
      - name: Configure
        run: cmake --preset vcpkg-release

      - name: Check translations are up to date
        if: runner.os == 'Linux'
        run: |
          cmake --build build-release --target update_translations
          git diff --exit-code -- translation/app_ru.ts translation/app_en.ts

      - name: Save vcpkg binary cache
```

This runs once (Linux leg of the matrix only — translations aren't platform-specific) and fails fast, before the ~25-minute full build, if any `tr()` string was added or changed without a matching translation update.
